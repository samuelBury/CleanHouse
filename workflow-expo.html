CleanHouse - Workflow de Test iOS

Fiche pratique pour tester l'app sur iPhone

1. Developpement quotidien Instantane

Expo Dev Server (Hot Reload)

Pour le developpement au jour le jour. Les changements apparaissent en temps reel sur le telephone.

npx expo start

Quand : Modifications de code JS/TS, styles, logique, composants, ecrans.

Comment : Scannez le QR code avec l'appareil photo de l'iPhone.

2. Mise a jour OTA (Over-The-Air) ~30 sec

EAS Update

Met a jour l'app deja installee sans rebuild. Ideal pour tester sur l'app preview.

eas update --branch preview --message "description"

Quand : Vous voulez mettre a jour l'app preview installee sur le telephone.

Comment : L'app se met a jour automatiquement au prochain lancement.

3. Build complet EAS Long (queue)

EAS Build

Recompile entierement l'app native. Necessaire uniquement pour les changements natifs.

eas build --platform ios --profile preview

Quand utiliser :

  • Ajout/modification d'une dependance native
  • Changement dans app.json (permissions, icone, splash...)
  • Modification d'un plugin Expo

Astuce : Ajoutez --local pour compiler sur votre Mac (necessite Xcode, pas de queue).

Resume rapide

Type de changement Methode Temps
Code JS/TS, styles, logique npx expo start Instantane
MAJ app preview installee eas update ~30 sec
Nouvelle lib native / config eas build 5-30 min

Commandes utiles

Action Commande
Voir les builds en cours eas build:list
Voir un build specifique eas build:view [ID]
Annuler un build eas build:cancel [ID]
Build local (sans queue) eas build --platform ios --local
Soumettre a l'App Store eas submit --platform ios
